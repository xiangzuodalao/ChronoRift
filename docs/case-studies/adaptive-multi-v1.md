**Adaptive Multi：两个开发案例、一次针对性优化与独立 holdout，2026-09-13**

Adaptive 已取消强制三个 worker。最终开发轮中，GN-1 创建一个 worker，Root tokens 减少约 49%，但耗时基本不变，团队费用仍高约 38%；City Builder 选择零个 worker。未参与调优的 Mob Orientation holdout 中，Adaptive 慢 69.5%，已上报费用为 Single 的 3.64 倍，Root tokens 约翻倍。当前策略没有稳定消除重复调查和 Worker 尾部工作；减少 Root 工作与缩短关键路径仍需分别验证。

此前[固定三个 worker 的负结果](codex-v2-retest.md)继续保留。本文保留首次 Adaptive 的负结果，并单独报告唯一一次针对性优化后的新对照；不跨轮合并平均，不选择性替换较差结果。Holdout 的两路模型调查各一次，结果不参与后续调优。

[固定输入](adaptive-multi-v1/inputs.json)、[结果 JSON](adaptive-multi-v1/summary.json)、[CSV](adaptive-multi-v1/results.csv)和[审计](adaptive-multi-v1/audit.json)提供完整指标与计时元数据。原始 Session、工具参数及完整模型内容留在本地私有目录。

**实现与公平条件**

普通产品默认最多三个活跃 worker，已有 `--max-agents` 配置仍允许 1–4；本对照另由 Host 限制最多三个历史 worker 身份、全部是 Root 直接子代理，允许零个。分工提示要求任务能独立完成并替代 Root 后续工作；Root 整合有证据的结论，负责修改和最终候选验证。Worker 应在简洁交付结论、证据与未覆盖项后结束 turn，后续任务由 `followup_task` 恢复。Host 没有增加确定性分工、成功判定或模型重试机制。

表中 total tokens 包含输入、输出、缓存读取和缓存写入；费用是对应 SDK 价格表估算，不是 provider 账单。

每路使用 `openai-codex/gpt-5.6-luna/max`，Root 调查上限 20 分钟；worker 每轮 10 分钟、64 次执行工具调用，团队执行预算 256 次，`game_stop` 与协作控制不占执行预算。相同案例的项目 revision、问题、coding/game 工具、wall-clock 和执行预算固定；Multi 额外提供协作工具。Host 锁定 worker 模型、provider 和 thinking，限制历史身份数三、深度一。开发轮的独立协议审计通过。

每个代理记录 Pi stream-function 请求起止时间及单调时钟耗时；coding 工具记录请求、请求锁、取得锁和完成时间。Worker 的 `settledAt` 表示 Host 收到 Pi 结束结果，`finishedAt` 还包含资源清理。共享 candidate 锁保留，游戏仍运行于独立固定 stage。模型请求耗时包含 provider/传输等待；多代理累计时间可能重叠，不能直接相加成为关键路径。

**唯一一次优化与新开发对照**

依据上述阶段数据，只增加一条 Root 结束/重开规则：最小修复通过相关最终候选检查后结束并报告限制；只有实际失败、明确未覆盖的验收要求、证据冲突或后续源码变化，才重开等价方案或重复同一验证。Worker 仅提出另一方案不足以重开修复。该规则没有把运行检查当作完整验收，没有修改分工门槛、worker 生命周期、工具能力或锁。

**分析修正与 holdout 边界**

原始派生 summarizer 将 SDK 工具完成误当作 game 操作成功。上述 `busy` 返回具有合法的 `details.outcome:error`，但 `isError:false`；因此旧派生 `rootFinalValidationAt` 存在假阳性。模型结束后仅修正分析：同时检查领域结果，未观察到修改后成功 launch 时最终验证时间记为 `null`，另存最后成功基线 launch 及其早于修改的标记。只把对应成功 execution 的成功 query/stop 计入验证时间。原始记录和旧派生文件保留，修正结果写入新目录；不再触发模型调用。

选定未参与本轮调优的既有 Mob Orientation case，各完成一次 Single/Adaptive。公开源码预检与六项验收器对照通过，实际三个 Session 的模型、thinking、工具、预算及冻结产品审计通过。

Root 与 worker 重复读取核心源码并分别启动基线调查。两路 Root 都有九次 read、九次 game query；Adaptive 的 bash 从五次增至十次，并增加六次协作调用，Root tokens 增加 103.9%。这次没有观察到 Root 工作替代。额外 81.387 秒主要发生在首次编辑前：57.010→126.642 秒，增加 69.632 秒；Root 三次等待共 20.008 秒。Root 请求累计耗时增加 58.447 秒，团队锁等待仅 0.123 秒；请求和工具累计时间有重叠，不能直接相加解释因果。

原始 holdout 两路在 Pi 调用前因源仓库前提检查失败而停止，未产生模型请求，原目录、失败状态和日志保留。恢复时使用固定提交的公开源码归档与原有 Git 对象数据库，构建完整干净 checkout，逐文件核对 Git blob、HEAD、tree、完整 index 和所选项目 source hash；不是以普通 clone 成功作为证据。所选 Mob 项目仍为 `711822a319c4333a8740522f3c71e97783199fb0`，内容 hash 与原准备输入一致。

仅修正 runner 对嵌套项目 `3d/squash_the_creeps` 的显式 `projectRoot` 传递。除 `run.mjs` 外，runtime、协作策略、工具、模型、预算和问题均与最终开发轮保持一致；运行产品整体 hash 因 runner 修改变化，恢复记录单独保存前后 hash 和文件差异证明。这是零模型调用失败后的启动准备恢复，不是第二次性能调优，也没有替换较差模型结果。

**验收、验证与限制**

两轮开发模型实验之前各有 15 项独立验收器对照通过；每轮四个最终补丁各独立验收两次，开发阶段共 16 次通过；holdout 两个最终补丁再各验收两次，四次通过。正式模型调查共十次，独立验收共二十次；另有两次未进入模型的 holdout 失败启动。这些重复检查不增加模型试验样本量。

GN-1 验收覆盖四个平台初始几何、精灵和 shape 身份，未模拟完整玩家触发/下落时序。City 验收覆盖初始化、120 次 process 空闲窗口、15 个模型双向切换、回绕、双键抵消与旋转；66 个相关断言不是 66 次独立实验。Mob holdout 按既有三种固定随机种子检查朝向、竖直速度及声明的水平速度范围，不覆盖完整玩法或随机分布。

最终 `corepack pnpm check` 通过 lint、格式、类型检查与 130 个测试文件中的 1016 项测试；实验脚本测试 24/24 通过。本轮此前的 `corepack pnpm test:godot` 为 13 个文件、20 项测试通过，SRT sandbox conformance 为 6 个文件、10 项测试通过；之后未改动 Godot 或 sandbox 运行代码。最终数据审计核对 JSON/CSV、用量、计时、原始文件 hash 与隐私投影均通过。无阻塞或跳过的必要检查。

本轮每个案例/模式/声明阶段只有一次模型试验，开发案例已知且参与调优，同一阶段共享机器与 provider 容量；模型轨迹、缓存、输入错误和工具失败都可能影响描述性差额。取消中的 provider 用量可能缺失，费用为 SDK 估算。它支持继续按 Root 工作量与关键路径评估 Adaptive，不支持普遍优于 Single、固定节费比例或更高成功率的结论。
